# Live-Quiz am Dienstabend — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Live-Quiz im Modul `feedback`: Handys antworten per QR, der Beamer (auch als iframe in Slidev) zeigt Fragen, Ergebnisse und Rangliste per Server-Push.

**Architecture:** Vier neue Tabellen in der Feedback-Datenbank. Eine reine Zustandsrechnung macht aus (Schritt, Zeit) die Ansicht. Ein Verteiler im Prozess schickt nach jedem Schreiben den vollen Zustand über SSE-Route-Handler. Öffentliche Ansichten ohne antd, Admin mit antd. `LiveQuiz.vue` setzt Slidev-Klicks per `postMessage` in absolute Schritte um.

**Tech Stack:** Next.js 16 Route Handler (`ReadableStream`), Drizzle + better-sqlite3, React 19, CSS-Module, antd 6 (nur Admin), Vitest, Playwright, Vue 3 (Slidev-Komponente, nur als Datei).

**Spec:** `docs/superpowers/specs/2026-11-25-live-quiz-design.md`

## Global Constraints

- Alle Regeln aus `CLAUDE.md` (Fallen 1–25) gelten. Besonders: kein antd und keine `--ant-*` in Beamer/Handy (Falle 2), keine Werte aus `"use client"`-Modulen in RSC (Falle 6), Icons nur `Icons8Ikone` (Falle 7), Zeitzone nur über `core/zeit` (`zeitzone()` / `kalendertagInZone`).
- Abenddatum = Mitternacht UTC des Kalendertags in der Suite-Zone: `new Date(kalendertagInZone(now) + "T00:00:00Z")`.
- Jeder neue Weg, der `evenings` beschreibt, hält die Tagesregel (`abendAmTag` in derselben Transaktion) und kommt in `ERLAUBT` von `_db/tagesregel.test.ts`.
- Jede neue Tabelle steht in `core/audit/catalog.ts` → `AUDIT_TABLES.feedback`. Jeder neue Route Handler und jede Server Action steht in `core/audit/coverage-manifest.json`.
- Migrationen sind handgeschrieben (wie `0003`/`0004`) und stehen in `migrations/meta/_journal.json`.
- Öffentliche Wege liegen **außerhalb** von `(admin)`, Admin-Wege prüfen `assertGroupAccess` mit der `group_id` aus der Datenbank.
- Moderations-Secret: 32 Byte `randomBytes` → base64url. Beitrittscode: 6 Zeichen aus `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`.
- Lagebild speichert keinen Spitznamen, keine `antwortzeit_ms`, und `token_hash` ist nach dem Beenden NULL.
- Punkte: richtig = `Math.round(1000 * (1 - 0.5 * min(ms, zeit_s*1000) / (zeit_s*1000)))`. Ohne `zeit_s` gibt es 1000. Falsch = 0. Mehrfachauswahl zählt nur, wenn die gewählte Menge genau der richtigen entspricht.
- Push: höchstens 1 Ereignis je 200 ms je Runde (bündeln, das letzte gewinnt), Herzschlag `: ping` alle 15 s, höchstens 200 Abonnenten je Runde (danach 503).
- Auto-Ende: am Ende des Kalendertags (Suite-Zone) oder 6 h nach `schritt_seit`, je nachdem, was früher kommt.
- Commits: `feat(feedback): …` (Englisch). Body endet mit `Zunder: https://zunder.rubeen.dev/#/aufgabe/icgjszrho1y2fz59uwk95jqe`.
- Keine neuen npm-Abhängigkeiten; QR-Codes über `core/qr`.

## Review Focus

1. **Zwei Beamer-Tabs mit demselben Secret** (Slidev-Präsentermodus öffnet die Folie zweimal: Präsenter- und Publikumsansicht). Erwartung: beide senden denselben absoluten Schritt, es entsteht **eine** Runde und kein Hin- und Herspringen. Test in Task 3.
2. **Handy verliert kurz das WLAN** mitten in der Frage. Erwartung: Nach dem Wiederverbinden sieht es den aktuellen Zustand samt „Antwort ist da“. Die Teilnahme bleibt über das Cookie erhalten, es gibt keinen zweiten Beitritt. Tests in Task 3 und Task 6.
3. **Später Beitritt** (jemand scannt bei Frage 4). Erwartung: Der Beitritt geht, die Person steigt bei der laufenden Frage ein und hat für verpasste Fragen 0 Punkte. Test in Task 3.
4. **Antwort, die nach Ablauf von `zeit_s` ankommt** (langsames Netz). Erwartung: Der Server weist sie ab (409), das Handy zeigt „Zeit ist um“ statt eines Fehlers. Test in Task 3.
5. **Quizvorlage wird geändert, während heute eine Runde läuft.** Erwartung: Die laufende Runde behält ihren Schnappschuss. Test in Task 3.
